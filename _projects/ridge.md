## Overview

RIDGE connects remote-sensing data processing with real-time environments. The framework combines satellite imagery, digital elevation models, vegetation masks, building detections, and OpenStreetMap roads into terrain and object assets for Unity and X-Plane.

We developed RIDGE as a four-student graduation project at Başkent University, supervised by **Assoc. Prof. Emre Sümer**, with support from the **HAVELSAN SUIT program** and satellite data provided by **IMPROSAT**.

## My Contribution

I developed the **vegetation detection workflow for both Unity and X-Plane**, the **automated Unity preprocessing and export pipeline**, and the **Unity terrain material painter and its editor tools**. My work connected georeferenced satellite data to vegetation placement, simulator forest outputs, and material-painted terrain.

- Researched vegetation indices and selected NDVI as a transparent, configurable approach to vegetation detection without a trained neural network.
- Aligned NDVI imagery with georeferenced terrain tiles using reprojection and bilinear resampling, then generated vegetation masks, density maps, normalized tree positions, and NDVI statistics.
- Implemented procedural tree placement in Unity, with editor controls for placing, clearing, and toggling vegetation.
- Developed and integrated the X-Plane vegetation export, converting tree masks into georeferenced forest polygons and DSF text/scenery outputs.
- Built the automated Unity pipeline and Tkinter interface, including raw and prepared input modes, road/tree/building collision cleanup, missing-output completion, and a complete terrain package export.
- Developed HSV-based terrain material blending and a custom Unity Inspector for applying materials, loading presets, and restoring satellite textures.
- Evaluated tree and forest outputs against reference data using overlap, object-level, boundary, distance, and area consistency metrics.

RIDGE was a team project. I integrated the terrain, road, and building processing stages into the automated Unity workflow alongside my vegetation modules; the project also included my teammates’ terrain, building-detection, road-generation, and core X-Plane pipeline work.

## Unity Pipeline

I built the Python pipeline and Tkinter interface that bring the preprocessing stages together for Unity. Raw mode starts from RGB, DEM, and NDVI GeoTIFFs and prepares the terrain tile dataset. Prepared mode reuses existing tiles and supports skipping stages for repeated experiments. The interface exposes tile size, building detector settings, vegetation parameters, output folders, and run/stop controls with a live log.

The pipeline runs road processing, NDVI alignment and vegetation generation, and building detection in order. I implemented cleanup that removes trees from roads and removes road/tree regions from building masks, with an option to exclude colliding buildings from the exported JSON. Missing detections receive blank masks or empty JSON entries so every terrain tile remains represented. The final export collects metadata, RGB textures, height data, roads, trees, and cleaned building outputs into a Unity-ready `Terrain_Tiles` package.

## X-Plane Vegetation Integration

I developed the tree export module that converts RIDGE vegetation masks into forest polygons for X-Plane 12. Rather than exporting every tree as a separate object, it turns connected vegetation regions into polygons that X-Plane fills using a forest resource.

The exporter uses optional morphological cleanup and OpenCV contour extraction to identify forest regions and holes. It converts mask pixels into longitude and latitude using the matching GeoTIFF, simplifies contours, filters small regions, and sets the required winding directions for outer boundaries and holes. The resulting polygons are grouped by DSF tile and written in DSF2TEXT format for conversion with DSFTool and use in a custom scenery package. Density and optional exclusion settings control the generated forest output and default vegetation beneath it.

## Terrain Material Painting

I developed `TerrainMaterialPainter.cs` to turn satellite RGB textures into blended Unity terrain materials. Configurable HSV rules identify surfaces such as vegetation, dry farmland, concrete, and bare soil. Soft rule boundaries and normalized layer weights produce material transitions, while a fallback layer handles uncertain areas.

I also built the custom Inspector with controls to load the study-area preset, apply material masks, and revert to the original satellite texture.

## A Shared Spatial Workflow

1. Align satellite imagery and elevation data while retaining geographic metadata.
2. Prepare vegetation, building, and road representations.
3. Generate terrain and reusable scene assets for the target environment.
4. Export using the Unity and X-Plane workflows, with shared tile indexing and spatial references.

## Manuscript

**An automated spatial-data integration framework for satellite imagery, elevation data, and simulator-ready 3D terrain**

**Pelinsu Kaleli**, Bulut Demir, Alper Keskin, Zeynep Sude İmdat, and Emre Sümer.

Submitted to the Journal of Spatial Science.

The manuscript reports a building intersection-over-union score of **0.6564** with XUNet and vegetation intersection-over-union of **0.5189**, evaluated against manually digitized reference polygons in the study area. These are study-specific measurements, rather than a general accuracy claim for arbitrary imagery.
